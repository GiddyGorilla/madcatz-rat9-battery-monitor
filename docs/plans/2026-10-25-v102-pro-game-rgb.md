# Implementation Plan: V102 Pro Battery and Game Lighting

Status: Implemented and physically verified on 2026-10-25.

## Protocol correction

Hardware and current E HUB module investigation corrected two assumptions in
the initial design:

1. V102 uses `sdk-kbd-dakai`, not the Beiying command `0x87`.
2. V102 exposes global lighting effects, not an addressable per-key matrix.

The implementation follows the verified Dakai protocol.

## Delivered architecture

- `src/DeviceModels.cs`: shared identity and battery data.
- `src/V102Protocol.cs`: Dakai device, battery, and keyboard-configuration
  encoding.
- `src/V102HidDevice.cs`: Windows HID discovery, report I/O, and bounded retry.
- `src/V102BatterySource.cs`: battery and lighting adapter using one serialized
  HID handle.
- `src/V102BatteryHistory.cs`: persistent V102 samples and learned runtime.
- `src/V102LightingService.cs`: verified effect, palette, brightness, speed,
  breath/flow color, and logo-light configuration.
- `src/KeyboardProfileStore.cs`: atomic versioned JSON profile persistence.
- `src/GameProfileMonitor.cs`: two-second process matching with foreground
  priority and base restoration.
- `src/V102LightingForm.cs`: local profile and lighting editor.
- `src/Rat9BatteryTray.cs`: combined tray presentation and game integration.
- `src/TestHarness.cs`: deterministic protocol, profile, runtime, and process
  tests.

## Phase 1: V102 battery

Completed:

- Encode `55 AA 80`.
- Decode the verified `55 BB 80 20` response.
- Read percentage from byte 5 and charge-state bits from byte 4.
- Validate response command, status, and range.
- Preserve firmware, serial, mode, VID/PID, and MAC metadata.
- Discover VID `0x05AC`, PID `0x024F`, usage page `0x00C0`, usage `0x0001`.
- Verify physical response:
  - Model serial `257`.
  - Firmware `250928V201A`.
  - Battery/charging value matched E HUB.

## Phase 2: Combined tray and history

Completed:

- Add V102 polling on a serialized background worker.
- Combine R.A.T. 9 and V102 in one popup and tooltip.
- Show the lowest connected battery in the tray icon.
- Persist V102 samples for 30 days at five-minute resolution.
- Learn runtime from real discharge after at least 20 minutes and a 3-point
  drop.
- Do not seed V102 with a fabricated runtime.

## Phase 3: Lighting and profiles

Completed:

- Read current configuration with `55 AA 81`.
- Apply configuration with `55 AA 82 11`.
- Preserve sleep, idle, OS, Windows-key, and unrelated settings.
- Support animated effects `0–7`.
- Support static palette modes `16–24`.
- Support speed `0–4` and brightness `1–5`.
- Support breath/flow palette selection.
- Support all verified logo-light modes, including off.
- Save profiles atomically to:
  `%LOCALAPPDATA%\MadCatzRat9BatteryTray\v102-profiles-v1.json`.
- Read the current keyboard lighting back into the editor.
- Perform a no-op lighting write/read verification against the physical device.

Not implemented because it is not exposed by this model's official protocol:

- Independent RGB values for each individual key.

## Phase 4: Game profiles

Completed:

- Bind full normalized executable paths to profiles.
- Scan processes every two seconds.
- Prefer the configured foreground game.
- Use deterministic ordering when several games run.
- Restore the selected base profile after the last configured game exits.
- Retry after keyboard reconnect.
- Keep a manual non-base lighting choice until the next game transition.
- Never inject into games, read game memory, or interact with anti-cheat.

## Verification

Automated:

- `build.ps1` compiles and runs the V102 harness.
- Nine tests cover the HID command, physical response shape, charge bits,
  malformed data, runtime learning, lighting round-trip, persistence, and game
  priority/restoration, plus WinForms construction.

Physical:

- Windows opened the exact `2.4G` HID collection with report ID 0 and 65-byte
  input/output reports.
- Battery response parsed as 55–57% while charging during verification.
- Firmware/identity/MAC matched the connected V102.
- Current lighting configuration was read successfully.
- The verified configuration was written and read back unchanged.

Remaining release checks:

- Exercise each visual effect manually with the keyboard in view.
- Launch and close real configured games to confirm timing and reconnection.
